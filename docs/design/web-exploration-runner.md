# Design: Web exploration runner

## Goal

Test real web games/apps in a real browser, mirroring the Device Farm runner's loop and S3 output contract so the frontend renders both identically.

## Why a separate Fargate runner

Running headless Chromium in the Engine Lambda is not viable (memory/time). Instead the Web backend is its own ECS Fargate task (`agent/webExplorationRunner.mjs`, image `playagent-web-runner`, based on the Playwright image). The Engine only launches it and returns.

## Device driver

`playwrightClient.mjs` wraps Playwright with the same interface shape as the Appium client:

- `tap` → `mouse.click`
- `swipe` → wheel scroll or drag
- `type` → `keyboard.type` (+ Enter)
- `back` → `goBack`
- `launch` → `goto`
- screenshot / screen size / coordinate space / quit

## URL resolution

The start URL is resolved (in priority order) from: the case YAML `url:`, then the app's package/identifier (with `https://` added if missing), else a placeholder.

## Loop & output

Identical to the Device Farm runner: screenshot → smart-resize → VLM → decide → act, writing `screenshots/`, `steps/`, `traces/`, annotated images, `report.json`, `status.json`, and the memory map to S3. The report is generated by the runner itself.
